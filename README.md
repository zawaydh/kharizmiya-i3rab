# مدرّب التفكير النحوي

**تدريب موجّه بخوارزميات الإعراب التفاعلية.**

منصة تعليمية مبنية باستخدام Next.js وSupabase، تقدّم الإعراب بوصفه سلسلة قرارات مترابطة عبر ثلاث مراحل: **التعلّم الموجّه، التدريب، والاختبار النهائي**، مع مسارات بصرية وحفظٍ تصاعدي للتقدم وشهادة إنجاز.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env.local`.
2. أضف:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` بوصفه سر خادم فقط، من دون بادئة `NEXT_PUBLIC`
3. نفّذ:

```bash
npm ci
npm run dev
```

إذا استبدلت ملفات المشروع أو ظهر مسار صحيح على هيئة 404 محليًا، شغّل نسخة تطوير نظيفة بدل دمج مجلد `.next` القديم:

```bash
npm run dev:fresh
```

لا ترفع `.env.local` أو `node_modules` أو `.next` إلى GitHub.

## الفحص قبل النشر

```bash
npm run check
npx playwright install chromium
npm run test:e2e
```

وبعد تثبيت Chromium مرة واحدة يمكن تنفيذ البوابة المحلية كاملة بأمر واحد:

```bash
npm run release:verify
```

يعمل `npm run preflight` ضمن `npm run check` دون تشغيل التطبيق، ويتحقق من اكتمال الانتقال إلى TypeScript، وسلامة الاستيرادات، وملفات Supabase الأساسية، وميزانية CSS. ويشغّل `npm run check` تدقيق **جميع** التبعيات، واختبارات المحتوى والتقدم والشهادة وDOM، وفحص الوصول الآلي، ويفرض حدود تغطية الكود، ثم يفحص TypeScript وESLint ويبني نسخة الإنتاج. اختبارات DOM الثقيلة تعمل في عمليتي Vitest منفصلتين (`test:dom:exercise` و`test:dom:where`) حتى لا تتراكم بيئة JSDOM داخل العامل نفسه أثناء بوابة الإصدار.

يشغّل `npm run test:e2e` نسخة البناء على Chromium بمقاسي الحاسوب والهاتف، ويفحص المسار العام، وقفل المصادقة، ورفض كتابة التقدم من دون جلسة، وعدم وجود تمرير أفقي، ويقارن حالتي صفحة البداية قبل الحل وبعده بلقطات مرجعية فعلية. يجب تنفيذ `npm run check` أو `npm run build` قبله. ينفّذ GitHub Actions الفحصين تلقائيًا عند كل Push أو Pull Request، ويحفظ لقطات وفيديو وتتبع Playwright عند الفشل.

### اختبار Supabase الحي بجلستين

اختبار التزامن الافتراضي يحاكي تعارض الكتابة داخل الذاكرة. وللتحقق من قاعدة اختبار حقيقية، شغّل التطبيق أو رابط Preview، وخصّص حسابًا اختباريًا، ثم مرّر القيم أسرارًا بيئية ونفّذ:

```bash
INTEGRATION_BASE_URL=https://preview.example \
NEXT_PUBLIC_SUPABASE_URL=https://project.supabase.co \
NEXT_PUBLIC_SUPABASE_ANON_KEY=... \
SUPABASE_INTEGRATION_EMAIL=test@example.com \
SUPABASE_INTEGRATION_PASSWORD=... \
npm run test:integration
```

يسجّل الاختبار الدخول مرتين للحصول على جلستين مستقلتين للحساب نفسه، ويرسل دليلين صحيحين بالتزامن، ثم يقرأ السجل عبر RLS ويتأكد من بقاء الدليلين. ويمكن بدل البريد وكلمة المرور تمرير `SUPABASE_INTEGRATION_ACCESS_TOKEN_A` و`SUPABASE_INTEGRATION_ACCESS_TOKEN_B` لجلستين جاهزتين. يفشل الأمر إن نقص متغير أو كانت الجلستان لمستخدمين مختلفين، ولا تُحفظ الأسرار في المستودع. يتوفر التشغيل نفسه يدويًا من GitHub Actions بعد ضبط أسرار الرابط وSupabase والحساب واتصال قاعدة البيانات المذكورة في ملف سير العمل.

ويشغّل المسار اليدوي نفسه رحلة حساب حقيقية على Chromium مرة واحدة: تسجيل الدخول، حفظ أدلة التعلّم والتدريب، فتح الاختبار، حفظ نتيجته، التحقق من لوحة التقدم، ثم فتح الشهادة. يستخدم افتراضيًا موضوع `ism-manqous` ويمكن تغييره عبر `SUPABASE_INTEGRATION_TOPIC_CODE`. لا يعمل هذا الاختبار صامتًا ضمن الفحص العام، بل يتطلب `RUN_AUTHENTICATED_E2E=1` وجميع متغيرات البيئة الحية.

## Supabase

### قاعدة الإنتاج الحالية

لا تشغّل `supabase/schema.sql` على القاعدة العاملة.

شغّل بالترتيب مرة واحدة فقط:

```text
supabase/migrations/20260803_production_schema_hardening.sql
supabase/migrations/20260805_server_authoritative_progress.sql
supabase/migrations/20260806_error_observability.sql
```

لا تحذف الملفات تقدمًا أو سجل طالب. الترقية الثانية تمنع تعديل النسب ونتيجة الاختبار والشهادة مباشرة من المتصفح؛ ويصبح الحفظ عبر `/api/progress` بعد التحقق من المثال والنتيجة على الخادم. تنشئ الثالثة سجل أخطاء الواجهة المقيد بالخادم. بعدها شغّل ملف القراءة فقط للتأكد من الأعمدة، وRLS، والفهارس، والسياسات، وسلامة البيانات:

```text
supabase/verify_current_schema.sql
```

يمكن فرض الفحص نفسه آليًا عبر اتصال Postgres مباشر:

```bash
SUPABASE_DB_URL=postgresql://... npm run verify:supabase
```

يعمل داخل معاملة قراءة فقط، وينهي الأمر بخطأ إذا وجد اختلافًا في الأعمدة أو الفهارس أو RLS أو السياسات أو المنح أو سلامة البيانات. يحتاج التشغيل اليدوي في GitHub Actions إلى سر `SUPABASE_DB_URL` إضافة إلى أسرار اختبار الحساب.

يُعد `supabase/add_certificate_earned_at.sql` ترقية قديمة منفصلة، ولا يلزم تشغيله بعد ملف الترقية النهائي.

### قاعدة جديدة

شغّل:

```text
supabase/schema.sql
```

ولا تشغّل ملفات `supabase/migrations` بعده؛ فهي سجل تاريخي فقط.

## النشر للتجربة

ارفع النسخة أولًا إلى فرع مثل `release-candidate` للحصول على رابط Vercel Preview. اختبر تسجيل الدخول، حفظ التقدم، المراحل الثلاث، المسارات البصرية، ولادة الشهادة وطباعتها. بعد نجاح الاختبار ادمج الفرع في `main`.

## بنية المشروع

- `app/components/TopicExercisePage.tsx`: بوابة موحدة لصفحات التعلّم والتدريب والاختبار.
- `app/components/ExercisePlayer.tsx`: تنسيق جلسة النشاط وإدارة العرض.
- `app/components/exercise/`: منطق العرض والجلسات والمكوّنات المفصولة؛ ملفات الحوار و«كان» ولوح السؤال واجهات صغيرة فوق وحدات متخصصة.
- `lib/exercise/`: محرك الإجابة، التقدم، الاختبار، والحفظ.
- `content/`: الأشجار والأمثلة وبنوك الأسئلة.
- `tests/`: اختبارات التراجع وسلامة المحتوى والواجهة.

## التعديل الآمن بعد التسليم

1. عدّل الملف المالك للميزة نفسها، واحذف القاعدة أو الدالة القديمة عند استبدالها؛ لا تنشئ ملف `old` أو `copy` أو طبقة إصلاح لاحقة.
2. لا تغيّر `content/**` أو `data/**` ضمن تعديل بصري أو تقني. أي تعديل تعليمي يجب أن يكون منفصلًا وتراجعه اختبارات المحتوى.
3. أضف CSS داخل الوحدة الدلالية القائمة. يمنع الاختبار تكرار المحدد/الخاصية، وانتشار المحدد العادي في أكثر من ثلاث وحدات، وتجاوز ميزانيات الأسطر والتصريحات.
4. ثبّت الاعتماديات بأرقام دقيقة. نفّذ ترقية React أو TypeScript أو ESLint الرئيسية في فرع مستقل، ولا تخلطها مع تعديل تعليمي.
5. قبل الدمج نفّذ `npm ci` ثم `npm run check` و`npm run test:e2e`.
6. في قاعدة الإنتاج لا تشغّل `schema.sql`. كل تغيير لاحق لقاعدة البيانات يكون بترقية مؤرخة جديدة، ثم `npm run verify:supabase` واختبار الحساب الحي.

- `10-shell-auth-exercise.css`: الغلاف العام والمصادقة والمكوّنات المشتركة.
- `20-navigation-paths.css`: مساعدات التنقل.
- `30-start-learning-core.css`: صفحة البداية التعليمية.
- `31-start-page-flow.css`: بنية التقدّم والنتيجة والمتابعة الخاصة بمسار صفحة البداية.
- `40-learning-flow.css`: تدفق التعلّم الموجّه.
- `50-exercise-workspace.css`: مساحة التدريب والاختبار.
- `60-exercise-stability.css`: قواعد الثبات المشتركة للسؤال والحركة.
- `61-exercise-feedback.css`: التصحيح، والتغذية الراجعة، وثبات النتيجة.
- `70-exercise-flow.css`: حركة السؤال والسلوك المشترك لصفحات النشاط.
- `71-quiz-remedial.css`: المعالجة اللاحقة الخاصة بالاختبار.
- `72-text-game.css`: لعبة النصوص والحركات.
- `73-paths-dashboard.css`: رسائل الحالة في المسارات ولوحة التقدم.
- `74-speech-game.css`: نشاط «الإعراب في كلامنا».
- `79-navigation-system.css`: النظام النهائي للقائمة والتنقل.
- `80-page-system.css`: قواعد الصفحات العامة النهائية.
- `80-clean-system.css`: النظام البصري المشترك المتبقي.

يعلن `00-foundation.css` ترتيب طبقات cascade قبل أول طبقة فعلية حتى يبقى الترتيب صحيحًا بعد دمج ملفات الإنتاج. ولا يحمّل `app/globals.css` ملفات النشاط الثقيلة عالميًا: ملفات `30` إلى `74` و`83` تُستورد من الصفحة أو اللعبة التي تستخدمها فقط، و`31` لا يُحمّل إلا في `/learn/start`، وملفا الدليل من تخطيط `/guide`. عند استبدال قاعدة CSS تُحذف القاعدة القديمة، ولا تضاف طبقة موازية لها.

## مدرّب التفكير وتعليمات قبل التدريب

- تغيّر اسم قسم الموضوعات في التنقل إلى **مدرّب التفكير**؛ وهو المسار التفاعلي سؤالًا خطوةً خطوة.
- يوجد قسم مستقل باسم **تعليمات قبل التدريب** بالتفرعات نفسها؛ يجهّز الطالب للفكرة والخطوات قبل بدء النشاط التفاعلي.
- لكل موضوع جاهز صفحة شرح تشمل: الهدف، نقطة البداية، خطوات القرار وسبب كل خطوة، مثالًا كاملًا، وأخطاء شائعة.
- ينتقل الطالب من صفحة الشرح مباشرة إلى مدرّب التفكير، وإلى المسار البصري عندما يكون متاحًا.
## الألعاب الإعرابية

- `/games`: صفحة الألعاب.
- `/games/where-is-my-place`: لعبة «أين مكاني؟» في سبع دورات، كل دورة سبعة أمثلة جديدة من موضوعات متنوعة.
- `/i3rab-in-our-speech`: لعبة «الإعراب في كلامنا».

تعرض «أين مكاني؟» تفسيرًا خاصًا لكل اختيار خاطئ، وتوضح الصورة التي تحتاجها الجملة والوظيفة الإعرابية التي حكمت الحركة.
